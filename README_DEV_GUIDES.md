# README: Development Guides & Roadmap Usage

This file documents the process for using, referencing, and maintaining the development guides and roadmap throughout the project lifecycle.

---

## Purpose
- The guides in /uplink2/ are the authoritative step-by-step references for building each system.
- The roadmap (UplinkNextGen_Roadmap.md) is the high-level vision and milestone tracker.
- All guides and the roadmap must be kept in sync and marked off as features are completed.

## Workflow
1. Before starting any implementation, consult the relevant guide(s) and the roadmap.
2. As features are built, mark progress in both the guide and the roadmap.
3. Update guides with new best practices, discoveries, or changes in requirements.
4. Ensure all guides are stored in /uplink2/ and named consistently (DEV_GUIDE_XX_...).
5. Use the guides for onboarding, code reviews, and QA.
6. When a feature is complete, check it off in both the guide and the roadmap.

## Folder Structure
- /uplink2/UplinkNextGen_Roadmap.md (master roadmap)
- /uplink2/DEV_GUIDE_XX_... (detailed step-by-step guides)
- /uplink2/DEV_DOCS_INDEX.md (index of all guides)

## Best Practices
- Never start building a feature without a completed, referenced guide.
- Keep guides and roadmap up to date in parallel.
- Use guides for all contributors and as the source of truth for process.

---

This ensures a world-class, organized, and maintainable development process. Ready to begin building once all guides are in place and referenced!
